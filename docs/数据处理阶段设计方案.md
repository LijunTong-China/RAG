# 财务报表 RAG 系统 —— 数据处理阶段设计方案

> 版本：v1.1（三个开放问题已拍板，本阶段设计定稿）
> 阶段范围：仅数据处理（PDF → JSON → MD 校验 → 页级摊平 → 逐页切片 → 入 Milvus）
> 拍板记录：① 输入递归扫描统一文件夹下全部 PDF；② 切片重叠 100 token；③ Milvus Docker 自部署，embedding 用 Agicto text-embedding-v4（2048 维）

## 1. 总流程与数据流转

五步串行，**每一步的输出单独放一个编号文件夹，每一步都必须有落盘产物**，任何一步失败只回退到上一步的产物重跑：

```
data/00_raw_pdfs/          （输入，只读，递归扫描全部子文件夹）
        │  步骤1：MinerU 解析
        ▼
data/01_mineru_json/       每份财报一个子目录，MinerU 原始 JSON + 图片
        │  步骤2：JSON → MD，人工核对
        ▼
data/02_check_md/          每份财报一份校验 MD + 核对记录
        │  步骤3：摊平 JSON（财报级元数据 + 页级纯文本）
        ▼
data/03_flattened/         每份财报一个摊平 JSON
        │  步骤4：逐页切片（300 token/片，重叠 100 token）
        ▼
data/04_chunks/            每份财报一个切片大 JSON（含步骤3完整信息）
        │  步骤5：向量化（text-embedding-v4）+ 写入 Milvus（Docker）
        ▼
Milvus collection: financial_reports
                           （另产出入库对账报告 data/logs/）
```

## 2. 目录规划总表

根目录：`case/case35/RAG/`

| 文件夹 | 放什么 | 谁产出 | 性质 |

## 3. 通用约定

### 3.1 输入扫描与文件对照表（拍板①的落地）

PDF 统一放 `data/00_raw_pdfs/`，**允许子文件夹嵌套**。处理前先跑一次扫描（步骤0）：

1. 递归扫描 `00_raw_pdfs/` 下**所有子文件夹的所有 PDF**，逐个登记到 `data/manifests/file_manifest.csv`：

```csv
pdf_path, file_name, parsed_company, parsed_stock_code, parsed_report_type, parsed_period, parse_status
00_raw_pdfs/2023年报/贵州茅台_600519_年报_2023.pdf, 贵州茅台_600519_年报_2023.pdf, 贵州茅台, 600519, 年报, 2023, ok
00_raw_pdfs/乱命名的报告.pdf, 乱命名的报告.pdf, , , , , need_manual
```

2. 文件名可按 `{公司名}_{股票代码}_{报告类型}_{报告期}` 解析的 → `parse_status=ok`，元数据自动获取
3. 解析不了的 → `parse_status=need_manual`：**该 PDF 停在流水线外**，由人工在对照表里补填公司名等字段（对照表补填后作为元数据唯一来源）——不猜、不兜底赋值
4. 步骤1 只处理对照表中 `ok` 或"人工已补填"的条目；`need_manual` 清单每次运行时输出提醒

### 3.2 标识符

- `report_id` = PDF 文件名去扩展名，全局唯一（对照表中不可重名，重名在扫描时即报错）
- `chunk_id` = `{report_id}::p{页码}::c{页内序号}`，例：`贵州茅台_600519_年报_2023::p87::c03`（页码 1 基，序号 0 基三位补零）

### 3.3 embedding 与 token 口径（拍板③的落地）

| 项 | 定稿值 |
|---|---|
| embedding 模型 | **Agicto 平台 `text-embedding-v4`**（OpenAI 兼容 `/v1/embeddings`），key 走环境变量 `AGICTO_API_KEY` |
| 向量维度 | **2048**（v4 支持多档维度，此处固定 2048；请求参数 `dimensions: 2048` 显式指定，避免平台默认值变化） |
| Milvus 度量 | COSINE（由 Milvus 负责余弦计算，两侧无需自行归一化） |
| 「300 token」计数器 | v4 无公开 tokenizer：切片计数用**近似 tokenizer**（tiktoken `o200k_base`）估算，单片按 ≤300 计。近似口径带来的误差不影响检索（单片远小于 v4 的 8192 上限），但**建库与查询必须用同一把尺子** |

## 4. 步骤1：MinerU 解析 PDF → JSON

- **输入**：对照表中放行的 PDF（§3.1）
- **处理**：逐份调用 MinerU；单份失败只记失败不影响其他份，重跑粒度 = 单份财报
- **输出**（必须落盘）：
  - `data/01_mineru_json/{report_id}/{report_id}_content_list.json` —— 后续步骤的唯一数据源
  - `data/01_mineru_json/{report_id}/{report_id}_middle.json` —— 备用（完整版面信息）
  - `data/01_mineru_json/{report_id}/images/` —— 版面截图
  - `data/logs/step1_mineru_report.json` —— 成功清单、失败清单+原因、每份页数
- **使用约定**：切块链路只认 `content_list.json`（平铺结构，块带 `type`/`page_idx`，表格带 `table_body` HTML 与 `table_caption`）

## 5. 步骤2：JSON → MD 校验

- **输入**：`data/01_mineru_json/{report_id}/{report_id}_content_list.json`
- **渲染规则**：text 块 → 段落；table 块 → markdown 表格（保留表标题/表脚注）；image 块 → `![图题](images/...)` 占位；每页开头插入 `<!-- ===== 第 N 页 ===== -->` 页标记
- **输出**（必须落盘）：`data/02_check_md/{report_id}.md` + `data/02_check_md/qa_records/{report_id}.md`（人工核对记录：抽检页、结论、日期）
- **校验方法**：每份固定抽 5 页（第 1 页、目录页、随机正文 2 页、表格最多的 1 页）对照原 PDF
- **通过标准**：任一抽检页出现**数字错误或表格结构错乱 = 不通过** → 调 MinerU 参数重跑该份（回步骤1）再抽检。只通过/不通过，无"大致还行"

## 6. 步骤3：摊平 JSON（财报级元数据 + 页级纯文本）

- **输入**：通过校验的 `content_list.json`
- **摊平规则**：
  1. 块按 `page_idx` 分组到页
  2. 页内按原顺序拼接：text 块取纯文本；table 块转逐行文本（HTML 表 → markdown 行式文本，含表标题）；image 块以 `[图: {图题}]` 占位
  3. 页与页之间不合并，页内不做额外加工
- **输出**（必须落盘）：`data/03_flattened/{report_id}.json`：

```json
{
  "report_id": "贵州茅台_600519_年报_2023",
  "metadata": {
    "report_name": "贵州茅台_600519_年报_2023",
    "company": "贵州茅台",
    "total_pages": 120,
    "source_pdf_path": "data/00_raw_pdfs/2023年报/贵州茅台_600519_年报_2023.pdf",
    "mineru_json_path": "data/01_mineru_json/贵州茅台_600519_年报_2023/贵州茅台_600519_年报_2023_content_list.json"
  },
  "pages": [
    { "page": 1, "text": "本页全部内容的纯文本……" },
    { "page": 2, "text": "……" }
  ]
}
```

- 元数据 = 四个基础字段 + `total_pages`（总页数，摊平完成时按 pages 数组统计）；报告类型/报告期/股票代码/章节等按需求**后续根据 MinerU 元素内容增加**（metadata 对象直接扩字段，结构不变）
- **报告**：`data/logs/step3_flatten_report.json` —— 每份页数、每页字符数、含表格页清单
- 页 `text` 为空（扫描件无文本层等）：**保留空页并标记，报告列清单**，不跳过不编造

## 7. 步骤4：逐页切片（300 token/片，重叠 100 token）

- **输入**：`data/03_flattened/{report_id}.json`
- **切片规则**：
  1. **逐页独立切片**：切片边界不越过页（每片页码元数据唯一真实）；页尾不足一片的部分并入该页最后一片，不跨页拼接
  2. 每片目标 ≤300 token，按句子边界聚合封片；单句超 300 token 时句内二分（仅超长表格行会出现）
  3. **相邻切片重叠 100 token**（拍板②）：滑动窗口步长 = 300 − 100 = 200 token；实现上下一片从上一片封片点回退约 100 token 的最近句子边界开始，保证重叠落在句子边界上
  4. token 计数按 §3.3 近似口径
- **输出**（必须落盘）：`data/04_chunks/{report_id}.json` —— 与步骤3组合的大 JSON（metadata、pages 全量保留 + chunks 数组）；metadata 在步骤3基础上追加 `total_chunks`（本份财报切片总数，封片完成后统计）：

```json
{
  "report_id": "贵州茅台_600519_年报_2023",
  "metadata": {
    "…同步骤3完全一致（含 total_pages）…",
    "total_chunks": 1386
  },
  "pages":    [ "…同步骤3完全一致…" ],
  "chunks": [
    {
      "chunk_id": "贵州茅台_600519_年报_2023::p87::c03",
      "chunk_index": 3,
      "page": 87,
      "token_count": 287,
      "text": "切片正文……"
    }
  ]
}
```

- **报告**：`data/logs/step4_chunk_report.json` —— 每份切片总数、token 分布（均值/中位/最大）、页均片数
- **质量约束**：无空切片；单片 ≤300 token；重叠片数量符合滑窗预期
- **数据量提示**：100/300 重叠使每页切片数约为无重叠的 1.5 倍，Milvus 存储量与向量化 API 调用量同步 ×1.5（拍板②的已知代价，接受后按此执行）

## 8. 步骤5：向量化 + 存入 Milvus（Docker 自部署）

### 8.1 Milvus 部署

- 方式：Docker Compose 单机版（Milvus Standalone），组件含 etcd / minio / milvus-standalone
- 端口：19530（gRPC）/ 9091（健康检查），数据卷挂 `deploy/volumes/`，配置文件放 `deploy/docker-compose.yml`
- 部署文件属步骤5产物，纳入 `deploy/` 文件夹管理

### 8.2 向量化与写入

- **输入**：`data/04_chunks/{report_id}.json` 全量
- **向量化**：每片 text 调 Agicto `text-embedding-v4`（`dimensions=2048`），批量请求（单请求多条 text，受平台单请求上限约束，代码阶段按 64 条/批起测）
- **Collection `financial_reports` schema**：

| 字段 | 类型 | 说明 |
|---|---|---|
| chunk_id | VarChar(256), 主键 | §3.2；按主键 upsert 天然去重 |
| vector | FloatVector(**dim=2048**) | 度量 COSINE |
| text | VarChar(4096) | 切片正文 |
| report_name | VarChar(128) | 哪份财报 |
| company | VarChar(64) | 哪家公司 |
| source_path | VarChar(256) | 财报存放位置（PDF 原始路径） |
| page | Int16 | 页码 |
| chunk_index | Int16 | 页内第几个切片 |

索引：HNSW（M=16, efConstruction=200），度量 COSINE。后续 metadata 扩展字段同步加列。

- **单份重灌**：重处理某份 = 按 `report_name` 删除旧数据再插入
- **输出**（必须落盘）：`data/logs/step5_milvus_report.json` —— 每份入库条数与步骤4切片数**逐份对账相等**；不一致 = 失败处理

## 9. 错误处理与重跑原则

1. 任一步单份失败：写日志，其余财报继续（批量不因单份阻塞）
2. 重跑粒度 = 单份财报单步骤：从上游文件夹既有产物出发
3. 闸门即文件夹：`02_check_md` 有"通过"结论的财报才能进步骤3；对照表 `need_manual` 未补填的 PDF 进不了步骤1
4. 所有取不到的值留空并在报告列清单，**禁止猜值兜底**

## 10. 每步输出物验收清单（总表）

| 步骤 | 必有输出 | 验收标准 |
|---|---|---|
| 0 | `data/manifests/file_manifest.csv` | 所有子文件夹 PDF 全部登记，无遗漏；重名已报错 |
| 1 | 01_mineru_json/ 每份一个目录 + step1 报告 | 放行 PDF 全部有 JSON 或失败记录，无静默遗漏 |
| 2 | 02_check_md/ 每份一份 md + qa_records | 每份有"通过"结论方可进入步骤3 |
| 3 | 03_flattened/ 每份一个摊平 JSON + step3 报告 | 页数与 MinerU 一致；空页已标记 |
| 4 | 04_chunks/ 每份一个切片 JSON + step4 报告 | 无空片；单片 ≤300；页码与 pages 对得上 |
| 5 | Milvus collection + step5 报告 | 逐份入库数 = 切片数；抽查 chunk_id 内容一致 |
