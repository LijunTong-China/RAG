# 配置说明 —— `config/pipeline_config.json`

> 原则：**可配置内容只存在于本配置文件**，脚本内不设默认值；任何配置项缺失/为空 = 直接报错终止（不兜底）。
> 修改本文件后无需改代码即可调整流水线行为。

## 1. paths —— 目录规划（对应设计方案 §2）

| 键 | 含义 |
|---|---|
| `raw_pdfs` | 原始 PDF 输入目录（只读，允许子文件夹） |
| `manifest_dir` / `file_manifest` | 对照表目录 / 对照表文件 |
| `mineru_json` | 步骤1 输出根目录 |
| `mineru_staging` | 步骤1 MinerU 暂存输出目录（脚本自动清理复用） |
| `check_md` / `qa_records` | 步骤2 校验 MD / 核对记录 |
| `flattened` / `chunks` | 步骤3 / 步骤4 输出 |
| `logs` | 各步骤报告（追加式） |

## 2. 文件名解析与对照表

| 键 | 含义 |
|---|---|
| `filename_pattern` | 文件名解析正则（去扩展名后匹配），命名组 `company` / `stock_code` / `report_type` / `period`。不可解析 → `need_manual`，人工补填，不猜值 |
| `manifest_columns` | 对照表 CSV 列序 |
| `manifest_status.ok` | 文件名正则自动解析成功的状态值 |
| `manifest_status.need_manual` | 正则与 LLM 均无法识别的状态值（停在流水线外） |
| `manifest_status.manual_filled` | 人工补填完成状态值（放行进步骤1） |
| `manifest_status.llm_filled` | LLM 识别成功的状态值（放行进步骤1） |

## 2.1 llm —— 文件名元数据识别（步骤0）

| 键 | 定稿值 | 说明 |
|---|---|---|
| `base_url` | Agicto OpenAI 兼容端点 | |
| `api_key_env` | `AGICTO_API_KEY` | key 只走环境变量（仅当存在正则不可解析的文件名时才需要设置） |
| `model` | `glm-5.3-flash` | 识别模型 |
| `temperature` | 0 | 保证识别确定性 |
| `cot` | true | 文件名识别启用 CoT：先内部逐步推理（去装饰前后缀→定位公司名→找代码→匹配类型→找年份），最终只输出 JSON |
| `max_retries` / `retry_wait_seconds` | 3 / 5 | 调用失败重试 |

识别约束（脚本内置，不可配置）：股票代码须 6 位数字、报告期须 4 位数字、报告类型限 年报/半年报/一季报/三季报/季报，任一不符合 = 识别失败 → `need_manual`，不猜值。

## 3. qa —— 步骤2/3 校验闸门

| 键 | 含义 |
|---|---|
| `pass_keyword` / `conclusion_field` | 核对记录中结论字段名与「通过」关键词；步骤3 检查 `抽检结论: 通过` 才放行 |
| `sample_pages.first_page` | 固定抽检：第 1 页 |
| `sample_pages.toc_search_max_page` / `toc_keyword` | 目录页在前 N 页内按关键词定位 |
| `sample_pages.random_body_pages` / `max_table_pages` | 随机正文页数 / 表格最多页数 |
| `sample_pages.random_seed` | 随机种子（保证抽检可复现） |

## 4. tokenizer / chunking —— 切片口径（拍板②③）

| 键 | 定稿值 | 说明 |
|---|---|---|
| `tokenizer.engine` / `encoding` | `tiktoken` / `o200k_base` | 近似计数器；建库与查询必须同口径 |
| `chunking.max_tokens` | 300 | 单片上限 |
| `chunking.overlap_tokens` | 100 | 相邻片重叠（必须小于 max_tokens） |
| `chunking.sentence_split_lookbehind` | `[。！？；!?;\n]` | 句子边界字符类（正则，用于 lookbehind 切句） |

## 5. mineru —— 步骤1 云端 API（https://mineru.net/api/v4）

| 键 | 含义 |
|---|---|
| `api_base` | API 根地址 `https://mineru.net/api/v4` |
| `api_key` | API 管理页面自建 Token（请求头 `Authorization: Bearer {api_key}`；错误码 A0202/A0211 时到这里更换） |
| `model_version` | `pipeline`（默认）/ `vlm`（推荐）/ `MinerU-HTML` |
| `enable_table` / `enable_formula` / `language` | 表格/公式识别开关、文档语言（默认 ch） |
| `batch_limit` | 批量上传单批文件数上限（接口上限 50） |
| `poll_interval_seconds` / `poll_timeout_seconds` | 轮询间隔与超时 |
| `zip_content_list_suffix` | 结果 zip 内 content_list 文件后缀（`*_content_list.json`，须恰为 1 个） |
| `zip_middle_name` | 结果 zip 内中间版面文件名（`layout.json`，落盘为 `{report_id}_middle.json`） |
| `images_dir_name` | zip 内图片目录名（解包到 `{report_id}/images/`） |

限制（平台侧，代码不重复校验）：单文件 ≤200MB、≤200 页；每日 1000 页最高优先级额度。

## 5.1 prompts —— 提示词统一管理

| 键 | 定稿值 | 说明 |
|---|---|---|
| `file` | `config/prompts.yaml` | **所有 LLM 提示词集中在这一个 YAML 文件**，键名管理、带编号注释，脚本零硬编码 |
| `autocheck` | true | step2 是否启用 LLM 自动校验 |

提示词键清单（详见 prompts.yaml 顶部登记）：`filename_parse_system`（step0）、`filename_parse_cot`（step0 CoT）、`md_autocheck_system`（step2）；召回阶段提示词（query 改写、召回页生成）已预留注释位。改提示词只动 YAML，不改代码。

## 6. embedding —— 步骤5 向量化（拍板③）

| 键 | 定稿值 |
|---|---|
| `base_url` | Agicto OpenAI 兼容端点 |
| `api_key_env` | key 所在环境变量名 `AGICTO_API_KEY`（运行前需设置，缺失即报错） |
| `model` / `dimensions` | `text-embedding-v4` / 2048 |
| `batch_size` | 单请求条数（Agicto text-embedding-v4 实测 64 条会返回空数据，定为 10） |
| `max_retries` / `retry_wait_seconds` | 批次失败重试次数与间隔 |

## 7. bm25 —— 步骤6 稀疏检索索引（与向量同规格）

| 键 | 定稿值 | 说明 |
|---|---|---|
| `index_dir` | `data/05_bm25` | 每份财报一个 `{report_id}.pkl` |
| `tokenizer` | `jieba` | 分词器；建索引与查询必须同一把尺子 |
| `k1` / `b` | 1.5 / 0.75 | BM25Okapi 参数 |
| `stopwords` | （不配置） | 可选：停用词文件路径，配置了就必须存在，不兜底 |

与向量链路同要求：同输入（`04_chunks`）、单份重灌（删旧 pkl 再建）、逐份对账（索引条数 == 切片数）、追加式报告 `step6_bm25_report.json`。查询接口：`step6_bm25.search(cfg, report_id, query, top_k)`。

## 8. milvus —— 步骤5 存储（拍板③）

| 键 | 定稿值 |
|---|---|
| `host` / `port` | `127.0.0.1` / `19530`（对应 deploy/docker-compose.yml） |
| `collection` | `financial_reports` |
| `metric_type` / `index_type` | `COSINE` / `HNSW` |
| `index_params.M` / `efConstruction` | 16 / 200 |
| `varchar_limits.*` | 各 VarChar 字段上限（设计方案 §8.2 schema） |

## 运行顺序

```bash
cd scripts
python step0_scan.py                                   # 扫描登记，人工补填 need_manual
python step1_mineru.py [--report_id xxx]               # MinerU 解析
python step2_render_md.py --report_id xxx              # 生成校验 MD + 核对记录模板
#   ↓ 人工在 data/02_check_md/qa_records/{report_id}.md 填写「抽检结论: 通过」
python step3_flatten.py --report_id xxx                # 摊平（闸门：核对通过）
python step4_chunk.py  --report_id xxx                 # 切片
python step5_milvus.py --report_id xxx                 # 向量化入库（先 docker compose up -d，deploy/ 目录）
```
