## 0.5 清空已灌数据（重新注入前执行）

> 目录职责（2026-09-23 改版）：
> - `data/original_pdfs/` —— **源 PDF 目录（人工放这里，只读不动）**，step0 扫描此目录
> - `data/00_raw_pdfs/` —— 派生工作目录：超限拆卷 + 未超限整本复制，**每次 step0 自动重建，无需手工清**
> - 其余 01~05 / manifests / logs 均为派生数据，可随时清空

```powershell

  Remove-Item -Force

# ② 清掉工作副本（step0 也会自动清，此处手工清等价）
Remove-Item data\00_raw_pdfs\*.pdf -Force

# ③ 删除 Milvus 集合（整库，比逐报告删更干净）
python -c "from pymilvus import connections, utility; connections.connect(host='127.0.0.1', port='19530'); [utility.drop_collection(c) for c in utility.list_collections()]"
```

> 换语料 = 把新 PDF 放进 `data/original_pdfs/`（换掉的源 PDF 删除即可），再执行 §7。

清空后从 step0 重跑全管线（见 §7）。

## 4. 接口冒烟（不开浏览器直接验证召回链路）

```powershell
# ① 新建会话
$r = Invoke-RestMethod -Method Post http://127.0.0.1:8800/api/session/new
$sid = $r.session_id

# ② 提问（走完整链路：意图→拆解→Map循环→Reduce 汇总）
Invoke-RestMethod -Method Post http://127.0.0.1:8800/api/chat `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes(
    ('{"session_id": "' + $sid + '", "message": "中芯国际2024年营业收入是多少？"}'))) | ConvertTo-Json -Depth 5

# ③ 关闭会话（等价于页面 unload 时的 sendBeacon）
Invoke-RestMethod -Method Post http://127.0.0.1:8800/api/session/close `
  -ContentType "application/json" -Body ('{"session_id": "' + $sid + '"}')
```

对照验收口径（详见设计方案 §13）：
- 意图拒绝：发"今天天气怎么样" → 固定话术，且 `data/logs/qa_turns.json` 中该轮 `rejected: true`；
- 多任务拆解：发"A公司和B公司对比"类问题 → 日志 `tasks[]` 每任务独立 `sub_query_logs/loops`；
- 补充检索：`loops[]` 应能看到第 2/3 轮的 `verdict` 与 `new_pages`。

## 6. 常见故障对照

| 现象 | 原因与处理 |
|---|---|
| 启动即报 `Milvus 集合不存在` / 连接拒绝 | Docker 未起或容器未跑 → 回到 §1 |
| 启动报 `缺少字段 ['period','report_type','stock_code']` | 旧 schema 集合未删 → §2 的 drop_collection + 重灌 |
| 启动报 `BM25 索引缺失` | 报告没跑 step6 → §2 |
| 提问报 `环境变量 AGICTO_API_KEY 未设置` | 当前 shell 没设 key → §1 ③ |
| rerank 报 4xx/字段错误 | Agicto `/rerank` 响应格式不符 → 只需改 `qa/retrieval.py:rerank_pages` 的字段解析 |
| 回答为信息不足话术但预期有答案 | 查 `qa_turns.json` 对应轮的 `sub_query_logs`（filters 是否命中 0 份报告）与 `loops[].verdict` |

## 7. 全管线重跑（清空数据后从零重新注入）

```powershell
# 源 PDF 放入 data/original_pdfs/ 后，一键编排（langgraph，扫描 + 依次 step0~step6；
# 不传 --report_id = 跑全部放行财报）：
python scripts\pipeline_graph.py

# 或按报告分步执行（report_id = data/00_raw_pdfs 里工作副本文件名去扩展名；
# 源超 200 页被拆卷的，每卷一个 report_id，逐卷执行 step1~6）：
python scripts\step0_scan.py
python scripts\step1_mineru.py --report_id "<工作副本文件名去扩展名>"
python scripts\step2_render_md.py --report_id "<同上>"
python scripts\step3_flatten.py --report_id "<同上>"
python scripts\step4_chunk.py   --report_id "<同上>"
python scripts\step5_milvus.py  --report_id "<同上>"
python scripts\step6_bm25.py    --report_id "<同上>"
```

> step0 行为：扫描 `data/original_pdfs/`（源目录只读不动），超 `mineru.max_pages`(200) 的拆成
> `_partN.pdf`、未超限的整本复制，产物统一重建到 `data/00_raw_pdfs/`，并登记 file_manifest.csv。
> 当前语料：10 份 2025 年报 → 19 份工作副本（9 份拆卷 + 贵州茅台 1 份整本）。

重跑完成后回到 §3 启动问答服务（若服务在跑需先重启，启动自检会重新校验 Milvus 与 BM25）。
