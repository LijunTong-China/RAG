# 执行手册 —— 数据处理阶段（步骤0 ~ 步骤5）

> 对应设计文档：`docs/数据处理阶段设计方案.md`；所有可调参数见 `docs/配置说明.md`（`config/pipeline_config.json`）。
> 执行目录：以下命令均在 `case/case35/RAG/` 下运行。

## 0. 首次准备（只做一次）

### 0.1 依赖安装

```bash
pip install requests tiktoken pymilvus openai
```

### 0.2 放入原始 PDF

把全部财报 PDF 放入 `data/00_raw_pdfs/`，**子文件夹任意嵌套**，扫描器会递归收全。

### 0.3 启动 Milvus（仅步骤5需要，可最后再做）

```bash
cd deploy
docker compose up -d          # 首次会拉取 etcd / minio / milvus 三个镜像
# 健康检查：浏览器打开 http://localhost:9091/healthz 返回 OK 即正常
cd ..
```

数据卷落在 `deploy/volumes/`；`docker compose stop` 关闭保留数据，`docker compose down -v` 彻底清空（慎用）。

## 1. 步骤0：扫描登记对照表

```bash
python scripts/step0_scan.py
```

- 产出 `data/manifests/file_manifest.csv`
- 文件名符合 `{公司名}_{股票代码}_{报告类型}_{报告期}.pdf` 的自动登记 `parse_status=ok`
- 文件名解析不了的，自动调 Agicto `glm-5.3-flash` 识别元数据（需先设置环境变量 `AGICTO_API_KEY`），识别成功 `parse_status=llm_ok`
- 只有正则与 LLM 都识别不了的才进 `need_manual` 清单，此时才需人工在 CSV 补填并把状态改为 `manual_ok`（字段留空的行会在后续步骤报错，不会静默通过）
- **注意**：此 CSV 之后是元数据唯一来源；重跑本步会重新生成并覆盖

## 2. 步骤1：MinerU 云端解析

```bash
python scripts/step1_mineru.py                 # 全量
python scripts/step1_mineru.py --report_id 贵州茅台_600519_年报_2023   # 单份重跑
```

- 逐批（≤50 文件/批）上传到 MinerU API，轮询到完成后解包落盘
- 产出：`data/01_mineru_json/{report_id}/`（`*_content_list.json`、`*_middle.json`、`images/`）+ `data/logs/step1_mineru_report.json`
- 单份失败不影响其他份；失败明细在报告里，改完条件后用 `--report_id` 单份重跑
- **平台限制**：单文件 ≤200MB / ≤200 页；每日 1000 页最高优先级额度；token 过期（错误码 A0211）时到 `config/pipeline_config.json` 的 `mineru.api_key` 换新

## 3. 步骤2：生成校验 MD → 人工核对

```bash
python scripts/step2_render_md.py --report_id 贵州茅台_600519_年报_2023
```

- 产出 `data/02_check_md/{report_id}.md` + `data/02_check_md/qa_records/{report_id}.md`
- 每份财报都要跑一次
- **人工动作（闸门）**：打开 qa_records，按其中列出的抽检页（第1页、目录页、随机正文2页、表格最多的1页）**对照原 PDF 核对**，然后在文件里把结论行改为：

  ```
  抽检结论: 通过
  ```

  出现数字错误或表格结构错乱 → 写「不通过」，调 MinerU 参数（改配置 `mineru.model_version` 等）后从步骤1重跑该份，再抽检。只通过/不通过，没有"大致还行"。

## 4. 步骤3：摊平

```bash
python scripts/step3_flatten.py --report_id 贵州茅台_600519_年报_2023
```

- **人工抽检不阻塞**：qa_records 的抽检结论只作记录，未填也会继续执行（脚本会提示抽检状态，建议尽快补检）
- 产出 `data/03_flattened/{report_id}.json` + `data/logs/step3_flatten_report.json`
- 空页（扫描件无文本层等）保留并标记，报告里列清单，不跳过不编造

## 5. 步骤4：切片

```bash
python scripts/step4_chunk.py --report_id 贵州茅台_600519_年报_2023
```

- 逐页切片，300 token/片、重叠 100 token（数值在配置 `chunking` 段）
- 产出 `data/04_chunks/{report_id}.json` + `data/logs/step4_chunk_report.json`（切片总数、token 分布）
- 脚本自检：空切片、超 300、页码对不上都会直接报错终止

## 6. 步骤5：向量化 + 入库 Milvus

**前置**：Milvus 已启动（见 0.3）；环境变量已设置（与 MinerU 的 key 不同，这个只走环境变量，不进配置文件）：

```bash
set AGICTO_API_KEY=你的Agictokey        # cmd
$env:AGICTO_API_KEY="你的Agictokey"     # PowerShell
```

```bash
python scripts/step5_milvus.py --report_id 贵州茅台_600519_年报_2023
python scripts/step6_bm25.py   --report_id 贵州茅台_600519_年报_2023
```

- 每片调 Agicto `text-embedding-v4`（2048 维，64 条/批）写入 Milvus collection `financial_reports`
- **单份重灌**：同一条命令重跑即可，先按 `report_name` 删旧数据再插
- 入库后自动逐份对账：Milvus 条数 == 切片数，不等 = 失败并写报告

## 7. 两种执行方式

### 7.1 逐步骤手工执行（见 1~6 节命令）

### 7.2 LangGraph 一键编排（推荐，`scripts/pipeline_graph.py`）

```bash
python scripts/pipeline_graph.py                     # 全量：step0 扫描 -> 逐份跑图
python scripts/pipeline_graph.py --report_id xxx     # 只跑一份
```

每份财报执行的状态图：

```
step1_mineru → step2_render_md → qa_gate（记录抽检状态，不阻塞）→ step3_flatten → step4_chunk → step5_milvus → step6_bm25
```

- 人工抽检（qa_records 填「抽检结论: 通过」）随时可补，不填也不影响全链执行
- 任一节点异常：该份终止并汇总打印，不影响其他份
- 末尾汇总：完成 / 失败，并单列「待人工抽检」清单（仅提醒）

## 8. 排错速查

| 现象 | 处理 |
|---|---|
| step0 报 report_id 重名 | 两个 PDF 文件同名，改名后重跑 |
| step0 LLM 识别失败多 | 检查 AGICTO_API_KEY 环境变量；仍失败的人工补填对照表 |
| step1 HTTP/业务失败 A0202 / A0211 | token 错误/过期，换 `mineru.api_key` |
| step1 -60018 每日任务上限 | 明日再跑，或先跑其余份 |
| step1 -60005 / -60006 | 文件超 200MB / 超 200 页，拆分 PDF |
| step3 拒绝：未找到「抽检结论」 | qa_records 没填或格式不对，必须写 `抽检结论: 通过` |
| step5 报 AGICTO_API_KEY 未设置 | 该 key 只从环境变量读，见第 6 节 |
| step5 连不上 Milvus | `docker compose ps` 看容器是否健康，端口 19530 |
| 对账失败（入库数≠切片数） | 看日志后直接重跑该份 step5（幂等，先删后插） |

## 9. 安全提醒

- `config/pipeline_config.json` 内含 MinerU token 明文，勿提交公开仓库
- `AGICTO_API_KEY` 只放环境变量
